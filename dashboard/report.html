Project report · V1 · paper trading only

No edge found.

A multi-agent paper-trading system, built across six phases and evaluated honestly. It runs, it reasons, it deploys — and it does not beat buying the stock and holding it. This is the report of that result.

9 September 2026 AAPL · 7 real-LLM backtests Never touched real capital

The finding

Every backtest longer than a single quarter underperformed buy-and-hold, by $39 to $225 on a 20-share basis. The out-of-sample run — executed once, with no code, prompt or parameter changes made after seeing the in-sample result — lost $63 in a market that was essentially flat.

The project's founding rule was that an honestly evaluated failure is the correct thing to report. So it is reported, and the machinery built to detect it is the actual deliverable.

What was built

Six phases · five built · one closed on a negative result

The premise was to close six engineering gaps by building one real system rather than six disconnected exercises. Each phase produces something the next one depends on, and the sequence is real: nothing here is a numbered list of parallel tasks.

The agent graph

Four nodes, deliberately split by whether judgment is actually required. A Technical Analyst computes RSI-14 and SMA-20 in plain Python — arithmetic is not worth an LLM. A Sentiment Analyst reads headlines through GPT-4o-mini. A Portfolio Manager (GPT-4o) synthesises both into a proposal. A Risk Manager, rule-based again, holds final authority and can veto or scale any trade.

That last split — propose versus gate — is what made most of this report possible. Because the Risk Manager is code and every input it consumed is stored, alternative risk rules could later be tested for free.

Seven runs · real Alpaca prices · real LLM calls · 5bps slippage

Why mark-to-market, not realized P&L

Realized P&L alone made run #3 look like a clean 100% win rate and made run #14 look far worse than it was. Both had open lots carrying unrealized moves. Any run ending with open positions gets marked at the window's last price before being compared to anything.

A baseline error, found by checking a number that looked slightly wrong.

Run #4 covered 2022-06-01 → 2023-06-30. Runs #7, #8, #9 and #14 covered 2022-06-03 → 2023-06-30. AAPL fell 148.73 → 145.39 across those two extra days, moving buy-and-hold by $66.80.

Every earlier writeup had compared the ablation runs against run #4's baseline and concluded they "matched buy and hold". Against their own window they were $41–74 below it. The comparison tool had been printing the window for every run the whole time; nobody read it. It now refuses to be ignored.

Phase 04, in detail

The most instructive failure in the project

The goal was to replace the sentiment node's API call with a locally fine-tuned model. Four things were tried. All four are measured, and every measurement points the same way.

Two adapters, both degenerate

The second adapter predicted HOLD on all 44 held-out rows. It had learned the constant function. The first invented SELL calls on neutral headlines and reached 3.6% precision on BUY.

A database inventory explained both at once: across every backtest the teacher had produced 17 BUY, 3 SELL and 537 HOLD, on one symbol, over overlapping date ranges. Distilling a teacher that says HOLD 96.8% of the time yields a student that always says HOLD. The problem was never the hyperparameters.

Then the node itself was ablated

Before spending roughly 6,000 labelling calls on more training data, the node was removed and the system re-run — same graph, same Portfolio Manager, only the sentiment content replaced by a neutral stand-in. Removing it improved results by about 60 on a 13-month window, consistently, at roughly twice the measured run-to-run noise.

The mechanism was visible in the action counts. The node's near-constant HOLD votes read to the Portfolio Manager as a vote against trading, suppressing around nine BUYs and six SELLs that would have been profitable. An agent that abstains most of the time is not automatically harmless.

The rewrite worked, and traded worse

The node was rewritten to emit a continuous −1.0 to +1.0 tone score instead of a categorical vote — fixing the root cause of both failed adapters, since a score has real variance even on boring news and is therefore a trainable regression target.

It succeeded at exactly that. Across 281 days: range −0.50 to +0.50, mean +0.057, standard deviation 0.235, zero exact zeros, 184 positive and 97 negative days. No collapse.

And it produced the worst trading result of any configuration tested: +745.86 against a bar of +896/+930. It traded roughly twice as much — 62 closed trades against 32–33 everywhere else, at a 32% win rate. "The component works as specified" and "the system got better" are independent claims.

A confound, named rather than buried.

That run changed two things at once: the sentiment node and the Portfolio Manager prompt that reads it. The prompt change was designed to stop abstentions suppressing trades — and it worked, possibly too well. This run cannot attribute the extra trading to either cause. One further ablation would separate them; it has not been run.

Phase 04 was then closed rather than continued. The remaining labelling calls would have bought a better imitation of a component every measurement says to delete.

Testing rules without paying for them

Offline replay · zero API cost

The Risk Manager is rule-based, the Portfolio Manager's proposals are stored, and the price the agent saw each day is stored. So "what would a different risk rule have done?" is arithmetic over recorded data, not a new backtest. A replay tool re-gates every recorded proposal — and refuses to print anything unless its baseline reproduces the recorded run first. On the out-of-sample window it matches to $0.0003.

It was used to test the standing assumption that a drawdown rule would have saved the losing run. It would not have.

It also corrected the project's own recorded diagnosis. Three consecutive December buys into a decline had been named as the cause; they are 43% of the loss. The largest single contributor, 54%, is one September lot caught by a two-day 6.4% gap down that no add-to-position rule can anticipate. And the December decline was only ~1.1% from the first buy to the third, which is why a 2% threshold changes literally nothing.

Note also that three "different" rules land on exactly −49.24. They block the same two trades by three mechanisms. A table of seven rules was really testing about three ideas — worth knowing before anyone reports "we evaluated seven risk rules".

Bugs worth recording

Each one changed a conclusion or hid one

  1. A transaction bug made every backtest meaningless

    The first insert wasn't wrapped in its own transaction, so every later conn.transaction() silently downgraded to a savepoint and no day's writes were visible to the next day. The symptom was the position cap never engaging. Found before any result was trusted.

  2. Six database tests silently skipped for two entire phases

    On Windows, psycopg's pool cannot run on the default event loop. It raises PoolTimeout, which subclasses OperationalError, which the "no database available" guard caught. The suite reported green while running 33 of 39 tests. CI now fails if any test skips.

  3. A buy-and-hold baseline from the wrong window

    Two days' difference between runs moved the baseline by $66.80 and turned "matched buy and hold" into "$41–74 below it".

  4. A database URL pointing at 127.0.0.1

    Correct for a process on the host, wrong inside a container where it is the container's own loopback. Migrations failed with "Connection refused" while docker ps showed Postgres healthy — both true at once.

  5. An AMI lookup that churned the server

    most_recent = true meant a newly published image made Terraform propose destroying a running instance for no reason anyone asked for. A plan you cannot trust is a plan you stop reading.

  6. GitHub's OIDC claim carries numeric IDs

    The documented subject is repo:owner/name; the real one appends immutable account and repository IDs. AWS returns only "Not authorized" — uninformative by design, since naming the failed condition would let an attacker probe the policy. CloudTrail carries the actual claim.

Four of those six were only findable by running the thing for real. That is the argument for the deployment costing a few cents rather than being left as validated code.

The deployment

Applied, verified, destroyed — same day

Terraform builds a purpose-made VPC, a t3.micro running the container image, an ECR registry, four encrypted parameters, scoped IAM roles, and an EventBridge schedule wired through SSM. Images reach the registry through GitHub OIDC — short-lived tokens, no access key stored anywhere.

Defaults are chosen to be safe rather than useful. The schedule ships disabled, because every firing spends real money. The managed database is off, because a container costs nothing and the trade-off belongs to whoever pays. There are no inbound rules at all; shell access is through SSM Session Manager, so there is no open port, no bastion and no key to lose.

It ran one real cycle on AWS — real prices, real LLM calls, a real database write — and returned run_id 1 · SUCCESS · AAPL BUY conf=0.65. Then it was destroyed. Keeping it running would cost about $13 a month to trade a strategy already measured as having no edge; proving the deployment works is worth a few cents, and running it indefinitely is not.

What this demonstrates

And what it deliberately does not

A working FastAPI service over Postgres with hand-written SQL and a hand-rolled migration runner. A four-node LangGraph agent where each node's model choice is justified by whether judgment is required. QLoRA fine-tuning end to end, including distillation from a teacher model. Containerisation, CI against a real database, and infrastructure-as-code applied to a live cloud account.

More usefully, it demonstrates an evaluation discipline: out-of-sample runs executed once and never re-tuned; accuracy numbers checked against the majority-class baseline before being believed; components ablated before being improved; noise floors measured rather than assumed; and a confound named in the writeup instead of smoothed over.

It does not demonstrate a profitable trading strategy, and no part of this report should be read as investment advice. The system never touched real capital. Its own conclusion is that it should not.

Left open, honestly

  • One further ablation would separate the score node's effect from the prompt change. It costs under a dollar and has not been run.
  • Every result is AAPL. A census of the headline dataset found 108 symbols with continuous coverage over the same window, so a second symbol is affordable and would test whether "no edge" is about the strategy or about one stock.
  • The evidence says remove the Sentiment Analyst from the graph. That is a design decision with consequences beyond this phase, so it was recorded rather than executed.

Paper trading only. This project never touched real capital or a live brokerage account, and nothing in it constitutes financial advice. The goal was an honestly evaluated system, not a claim of profitability — and when the evaluation came back negative, that is what got written down.
